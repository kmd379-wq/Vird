## По фигурам

### ФИГ. 23 — регистрация + транзакция `[PPA1-4]`

**На чертеже:** S670–S671 (скан + RFID + expiry) → S672 дверь → S687 возраст/депозит → S673 online/offline → S676 изъятие → корзина / тревога → S679 оплата; S688 возврат из корзины.

**В PPA1:**
- FIG.4 и текст: станция регистрации, barcode → RFID → expiry — **да**.
- Возраст / депозит, cloud vs local, alarm — **есть в теле** PPA1.
- «Добавить в корзину» / «изделие возвращено — удалить из корзины» — в PPA1 **нет** слов cart/basket/returned; логика учёта изъятий RFID есть, UI-корзина — добавка Ken (в PPA3 есть отдельные anti-return, но не эта блок-схема).

**Замечание по метке:** подпись «PPA1-4» верна только для левой (индукционной) части; правая ветка — скорее текст PPA1, не FIG.4.

### ФИГ. 24 — гравиметрический бункер `[PPA2-1]`

**На чертеже:** потолок, камера 2402 (визуальный аудитор), бункер 2412, товары 2410, тензодатчики 2414, опора 2416, электронный ценник 2418.

**В PPA2 FIG.1:** та же архитектура дословно.  
**Нюанс:** в кратком описании PPA2 FIG.1 ещё упомянуты *exit security scale*; на самой ФИГ. 24 их нет — выходные весы вынесены на ФИГ. 30. Это нормально.

### ФИГ. 25 — кривая bio-metric pricing `[PPA2-2]`

**На чертеже:** $/kg vs потеря влаги %; зона «Линейная» до θ; далее «Экспоненциальная скидка».

**В PPA2 FIG.2:** полное совпадение смысла и структуры.

### ФИГ. 26 — двухконтурный процесс `[PPA2-3]`

**На чертеже:** S680 мониторинг → S681 тип изменения → медленный дрейф (индекс свежести + цена) / внезапное падение (Δw → визуальный аудит → charge = Δw × P(t)).

**В PPA2 FIG.3:** полное совпадение.

### ФИГ. 27 — доступ к restricted goods `[текст PPA1]`

**На чертеже:** лицо/AI возраст/KYC → отказ или Unlock + депозит → online hold / offline буфер → отпирание → RFID-изъятие → итог при закрытии двери → списание / освобождение hold.

**В PPA1:** тот же сценарий в подробном описании (biometric interface, KYC, pre-authorization hold, offline deposit buffer, RFID removal, final charge).  
**Не из PPA2/PPA3 как основная фигура**, хотя PPA3 тоже имеет restricted + deposit.

### ФИГ. 28 — динамическое ценообразование `[PPA1 + PPA3]`

**Три ветки:**
1. Срок годности / скорость продаж / окно expiry — **PPA1** (+ PPA3 time-based decay).
2. Модель сенсорной деградации (время выкладки, T/H, камера) — **PPA3** (*sensory decay*; не слово «organoleptic» в EN).
3. Выручка на ячейку / уценка «свежий, но низкая оборачиваемость» — **PPA3** (*space-yield displacement*).

Плюс: локальный граничный контроллер при недоступности облака — **PPA1**; LED-подсветка уценённой зоны — **PPA1/PPA3**.

**Метка Ken корректна.**

### ФИГ. 29 — блокировка пополнения `[текст PPA2]`

**На чертеже:** W₀, ΔW%, lock, aggressive discount, refill detect, locked/clearance → lowest clearance unit price (i)(ii)(iii) → staff auth refill → новое W₀.

**В PPA2:** раздел Zero-Mixing / Refill Interlock — **дословное соответствие**.

### ФИГ. 30 — pay-as-you-pick `[текст PPA2]`

**На чертеже:** приближение → face/QR/BLE-UWB → session binding → Δw → vision audit → charge → запись → exit scales + reconcile.

**В PPA2:** раздел Pay-as-you-Pick — **совпадает**.

## Расхождения / риски для претензий

1. **Fig 23 «PPA1-4»** — завышена относительно исходной PPA1 FIG.4; шаги корзины/возврата лучше привязать к тексту или убрать метку «-4».
2. **Слово «корзина»** на Fig 23 не опирается на PPA1 EN; безопаснее формулировки «перечень извлечённых изделий» / RFID session list (как на Fig 27 S740).
3. **Exit scale** заявлен в PPA2 FIG.1, нарисован на Fig 30 — в описании PCT держать перекрёстные ссылки 24↔30.
4. **Fig 28:** в переписке/черновиках иногда «органолептика»; на фигуре и в PPA3 EN — *сенсорная деградация* — лучше унифицировать термин.
