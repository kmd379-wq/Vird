# Последовательность продажи: вход покупателя → выход  
## PPA №1 · PPA №2 · PPA №3 · черновик Ken (1756-1001PCT RU)

Сравнивается **логика и порядок шагов**, а не дословный текст.

---

## 1. Три разных «магазина» в одном слове «продажа»

| Источник | Что покупатель проходит |
|---|---|
| **PPA1** | Закрытый шкаф с дверью. Два режима: обычные продукты или алкоголь/табак. |
| **PPA2** | Открытая/зонная гравиметрическая станция (бункер на весах). Двери шкафа как центра нет. Выход = контрольные весы. |
| **PPA3** | Модульный шкаф. Для ограниченных товаров — сначала осмотр через смарт-стекло, потом дверь. Обычные товары — pay-as-you-pick. |
| **Ken** | Собирает №3 как каркас + №1 (биометрия/депозит/два режима) + №2 (гравиметрия/усушка/выходные весы) в одну платформу. |

Поэтому цепочка «вход → выход» **не одна**: у №2 другой физический сценарий, чем у №1/№3.

---

## 2. Пошаговая цепочка

### Шаг A. Покупатель подходит

| | Что происходит |
|---|---|
| **PPA1** | Подход к шкафу → биокамера / дисплей / платёжный интерфейс. |
| **PPA2** | Приближение к **зоне бункера** → детекция присутствия (движение, скелет, зона). |
| **PPA3** | Подход к шкафу → биометрия (для restricted) или платёжная авторизация (для ordinary). |
| **Ken** | Есть оба: подход к шкафу **и** к гравиметрическому бункеру/станции. |

**Вывод:** Ken покрывает A для шкафа и для гравиметрии.

---

### Шаг B. Идентификация / возраст

| | Что происходит |
|---|---|
| **PPA1** | В режиме ограниченных товаров: лицо → оценка возраста / KYC-match. Без прохождения — отказ. В режиме продуктов биометрия **не обязательна**. |
| **PPA2** | Не «возраст у двери», а **привязка сессии**: кто именно у бункера (лицо / QR / BLE-UWB / скелет) → дальнейшее изъятие вешается на этого пользователя. |
| **PPA3** | Для restricted: возраст/KYC. Для ordinary: может обходиться без биометрии. |
| **Ken** | Сохраняет оба смысла: возраст для limited goods + session binding у гравиметрии. |

**Вывод:** логика №1/№3 и логика №2 у Ken **рядом**, не смешаны в один шаг — это правильно.

---

### Шаг C. Осмотр до доступа (только restricted / PPA3)

| | Что происходит |
|---|---|
| **PPA1** | Нет смарт-стекла как обязательного этапа осмотра. Сразу биометрия → депозит → дверь. |
| **PPA2** | Нет. |
| **PPA3** | Смарт-стекло PDLC: непрозрачно → после возраста **прозрачный осмотр** + инфо о товаре («сомелье») → только потом платёжное обязательство и дверь. |
| **Ken** | Есть: непрозрачно → осмотр → платёжное обязательство → отпирание. |

**Вывод:** последовательность C у Ken = PPA3. В PPA1 этого звена нет — Ken его добавил из №3/Ali.

---

### Шаг D. Платёж / депозит до открытия

| | Что происходит |
|---|---|
| **PPA1** | Restricted: **pre-auth депозит** (сумма по профилю риска) → только после одобрения замок. Food: платёж/депозит проще или дверь уже доступна. |
| **PPA2** | Обычно **заранее** привязанный способ (кошелёк / hold на входе в зону), а списание — в момент изъятия. |
| **PPA3** | Restricted: депозит/обязательство после осмотра. Ordinary: авторизация, затем дверь и pay-as-you-pick. Плюс идея **поэтапной** блокировки за каждый товар. |
| **Ken** | Депозит / pre-auth / платёжное обязательство для limited; pay-as-you-pick для ordinary и гравиметрии. **Поэтапная поштучная блокировка PPA3 почти не раскрыта.** |

**Вывод:** D у Ken ближе к №1+№3, но без явного «hold на каждую единицу» из №3.

---

### Шаг E. Разблокировка двери / доступ к товару

| | Что происходит |
|---|---|
| **PPA1** | Замок двери после прохождения B+D (в restricted). |
| **PPA2** | Двери шкафа нет; доступ = возможность взять из бункера. |
| **PPA3** | Отпирание после C+D (restricted) или после оплаты (ordinary). |
| **Ken** | Отпирание шкафа как в №1/№3; для бункера — как в №2. |

---

### Шаг F. Изъятие товара + датчики

| | Что происходит |
|---|---|
| **PPA1** | RFID «передняя зона» + камера. Рука без метки → тревога / удержание депозита. |
| **PPA2** | Резкое падение массы Δw; камера проверяет жест; плата = Δw × P(t). Медленный дрейф массы ≠ покупка (это усушка). |
| **PPA3** | Ручное изъятие из модуля; комплексирование RFID/камера/вес; для gravity-gate — следующий товар только после подтверждения предыдущего; для restricted — тройное слияние. |
| **Ken** | Все три механизма описаны: RFID+камера; гравиметрия с двумя контурами; модули с профилями детектирования и затвором. |

**Вывод:** F у Ken полный по смыслу №1–3.

---

### Шаг G. Цена в момент продажи

| | Что происходит |
|---|---|
| **PPA1** | Цена из записи товара: срок годности + скорость продаж (+ LED скидки). |
| **PPA2** | Цена **за кг** непрерывно обновляется от усушки (кривая с порогом θ). В момент изъятия берётся текущая P(t). |
| **PPA3** | Цена от срока, **органолептики** и доходности ячейки. |
| **Ken** | Есть срок/скорость (№1), усушка/кривая (№2), доходность ёмкости ячейки (№3). **Органолептическая модель №3 как отдельный алгоритм — выпала.** |

---

### Шаг H. Защита от возврата / подмены

| | Что происходит |
|---|---|
| **PPA1** | В основном антикража на изъятии (нет храповика/штрафа за возврат как ядра). |
| **PPA2** | Нет anti-return двери; есть запрет смешивания партий при пополнении. |
| **PPA3** | Храповик / anti-return + штраф за возврат по весу + согласие с правилами до открытия. |
| **Ken** | Есть противовозврат и штрафы (линия №3). |

---

### Шаг I. Закрытие сеанса у шкафа

| | Что происходит |
|---|---|
| **PPA1** | Дверь закрылась / таймаут → финальный список товаров → списание из депозита → освобождение остатка. |
| **PPA2** | Сеанс живёт вокруг бункера; «закрытие двери» не центрально. |
| **PPA3** | Списание (в т.ч. поэтапно) + возможный автосброс просрочки в отходы (это уже фоновая логика, не шаг покупателя). |
| **Ken** | Финализация сеанса шкафа есть; автосброс/отходы есть как функция системы. |

---

### Шаг J. Выход покупателя

| | Что происходит |
|---|---|
| **PPA1** | Отдельных «контрольных весов на выходе» как обязательного звена нет. Выход = ушёл после закрытия двери и списания. |
| **PPA2** | **Ключевой финал:** контрольные весы на выходе сверяют суммарную массу с оплаченной. |
| **PPA3** | Выходных весов как ядра нет. |
| **Ken** | Выходные/контрольные весы и шлюз для плодоовощной/гравиметрической линии **есть** (из №2). |

**Вывод:** полный «магазинный» выход с весовой сверкой у Ken идёт из PPA2, не из №1/№3.

---

## 3. Сводная последовательность «как у Ken» (склеенный сценарий)

Типовой путь покупателя в черновике Ken:

```
1. Подход к шкафу / станции
2. Режим:
   ├─ ordinary → платёжная авторизация
   └─ restricted → биометрия возраста
                    → смарт-стекло: осмотр
                    → депозит / платёжное обязательство
3. Отпирание двери (если шкаф) ИЛИ доступ к бункеру (если гравиметрия)
4. Изъятие:
   ├─ полка/модуль → RFID + камера (+ вес модуля)
   └─ бункер → Δмасса × текущая цена/кг (с учётом усушки)
5. Антивозврат / аномалии датчиков
6. Закрытие двери / конец сеанса → списание / освобождение депозита
7. (для гравиметрии) контрольные весы на выходе
```

## 4. Где логика Ken совпадает и где ломается / дырявит

### Совпадает с описаниями PPA
- №1: биометрия → депозит → дверь → RFID/камера → финальное списание  
- №2: идентификация у бункера → изъятие по массе → цена от усушки → весы на выходе  
- №3: осмотр через стекло → обязательство → ручное изъятие из модулей → anti-return  

### Смешение (не ошибка, но важно видеть)
Ken **склеивает** три сценария в одну платформу. Покупатель «продуктов» и покупатель «алкоголя» и покупатель «весового овоща» идут разными ветками — в тексте это есть, но claim set ещё не разделяет ветки.

### Разрывы относительно исходных PPA
1. **PPA3 → Ken:** нет явной **поэтапной оплаты за каждый изъятый товар** в реальном времени.  
2. **PPA3 → Ken:** нет отдельного алгоритма **органолептической** цены (есть сенсорная деградация и доходность ячейки).  
3. **PPA1 → Ken:** в №1 выход = закрытие двери; у Ken выход часто дополнен весами №2 — это расширение, не противоречие.  
4. **PPA2 → Ken:** логика №2 сохранена, но звучит как модуль платформы, а не отдельный путь «магазин без двери шкафа».

## 6. Практический вывод

Последовательность продажи у Ken в целом **собрана правильно**:  
шкафовый путь №1/№3 и весовой путь №2 идут параллельными ветками и сходятся к оплате/выходу.

Чтобы логика совпала с исходными описаниями полностью, в текст Ken нужно явно вернуть в цепочку:
1) поштучную блокировку средств после каждого изъятия (PPA3);  
2) органолептическое звено цены до срока годности (PPA3);  
3) в будущей формуле — раздельные ветки «шкаф» и «гравиметрическая станция», иначе №2 растворится в №1/№3.
