## Краткое описание изобретения

Автономная торговая система с **контролируемым проходом** покупателя: на **входе** регистрируется переносимая тара (идентификатор + начальный вес), в **торговой зоне** фиксируются изменения массы тары при покупках, на **выходе** повторно проверяются идентификатор и вес **активной** тары и сравниваются с **ожидаемым** весом, рассчитанным по журналу событий сессии. При расхождении или подмене тары выполняется **защитная реакция** (блокировка, повторная проверка, оповещение). Поддерживаются: несколько единиц тары в одной сессии (своя + системная), зона возврата системной тары, двухзонная платформа (вес пользователя не учитывается), параллельные сессии у одного модуля.

### 3.2. Расчёт ожидаемого веса на выходе

```
ожидаемый_вес_на_выходе = Σ (активные_единицы_тары)

  для каждой активной единицы:
    вес = начальный_вес_тары
        + Σ события_добавления_в_тару
        - Σ события_изъятия_из_тары

  ИСКЛЮЧИТЬ единицы со статусом:
    ВОЗВРАЩЕНА, ОСТАВЛЕНА_В_ЗОНЕ (подтверждено), НЕАКТИВНА
```

### 3.3. Несколько покупателей у одного модуля (пункты формулы 20–23)

При параллельных сессиях контроллер распределяет события по:

1. Временной корреляции (метка времени)  
2. Зоне взаимодействия (слот / секция)  
3. id_тары активной ёмкости  
4. Траектории пользователя (камера)  
5. Последовательности событий датчиков  

Если уверенность < порога → **событие неоднозначности** → режим верификации; событие не дублируется в двух сессиях без правила распределения (пункт 23 формулы).

| 440 | Модуль защитной реакции | Блокировка, повторное взвешивание, инспекция, алерт оператору. |
| 450 | Модуль назначения ID тары | Назначает метку/ID при выдаче системной тары или режиме без метки. |
| 455 | Модуль идентификации тары | Считывает RFID/NFC/QR/штрихкод или создаёт временный ID. |
| 460 | Хранилище профилей тары | База профилей: тип тары, базовый вес, допустимое отклонение. |
| 470 | Облачная платформа | Удалённый сервер: аудит, аналитика, оператор (опционально). |
| 500 | Торговые модули | Smart-шкаф / полка: фиксирует изменение массы тары при покупке. |
| 600 | Двухзонная платформа | Зона 1 — тара на весах, зона 2 — пользователь (его вес не считается). |
| 610 | Зона 1 (тара) | Зона размещения переносимой ёмкости. |
| 620 | Зона 2 (пользователь) | Зона стояния пользователя. |
| 630 | Весовая структура платформы | Весовая часть двухзонной платформы. |
| 640 | Датчик присутствия пользователя | Фиксирует пользователя в зоне 2. |
| 650 | Камера / позиционирование | Камера и/или ограничители размещения (опционально). |

**Единица тары:** сумка, корзина, рюкзак, тележка или **системная корзина** магазина — каждая со статусом (активна / возвращена / оставлена / исключена с выхода).

**Боковой считыватель тары (пункт 2 формулы):** считыватель вдоль коридора — серия считываний при проходе для предотвращения подмены.

**Умная тара (пункт 8 формулы):** ёмкость со встроенным ID и, опционально, датчиками — прямая связь с контроллером.

# §5. Примеры применения

### Пример 1 — Модульный micro-shop в лобби ЖК (Micro Shop)

**Контекст:** автономная зона 3–6 smart-шкафов без кассира.

1. Покупатель подходит к **входной группе (100)**: на мониторе (110) — согласие на регистрацию своей сумки.  
2. Кладёт сумку на **двухзонную платформу (600)**: система фиксирует `id_тары` (NFC-бирка) и `начальный_вес = 420 г`.  
3. Дополнительно выдаётся **системная тара** (корзина магазина, 680 г) — вторая единица в сессии.  
4. В торговом модуле (500) покупатель снимает молоко и овощи — модуль отправляет **события изменения тары** (−1030 г, −500 г) в контроллер (400).  
5. Корзину магазина оставляет в **зоне возврата (210)** — контроллер меняет статус на «оставлена подтверждено», исключает 680 г из расчёта на выходе.  
6. На **выходе (300)**: активна только личная сумка; `ожидаемый ≈ 420 + 1530 = 1950 г`; факт 1940 г → **пропуск**, барьер выхода (320) открыт.

**Практический смысл:** контроль **непрерывности тары** вход→выход + учёт **нескольких** тар + **системная** корзина не создаёт ложное срабатывание на выходе.

---

### Пример 2 — Два покупателя у одного шкафа

**Контекст:** один торговый модуль (500), две параллельные сессии (пункты формулы 20–22).

1. Пользователи A и B одновременно в активных сессиях; у каждого свой `id_тары`.  
2. На одной весовой секции почти одновременно два события снятия товара.  
3. Контроллер (400) коррелирует: камера (650) + слот 3 → сессия A; слот 7 → сессия B.  
4. Если уверенность корреляции 45% → **событие неоднозначности** → обе сессии в режиме верификации, выход временно ограничен.  
5. Оператор или боковой считыватель разрешает неоднозначность → сессии закрываются нормально.

**Практический смысл:** масштабирование автономной розницы без ограничения «один покупатель на весь магазин».

# §6. Отличия от существующих и аналогичных решений

| Аналог | Что делает | Чего **нет** (наше отличие) |
|--------|------------|----------------------------|
| **Amazon Go / grab-and-go** | Компьютерное зрение, слияние датчиков, оплата по аккаунту | Сквозной **контроль конкретной переносимой тары** вход→выход; явная **верификация на выходе** (масса vs ожидаемая) |
| **Smart-холодильник / один шкаф** | Вес полки, списание при взятии | Нет контролируемого прохода; нет **мульти-тары в сессии** (своя + системная); нет логики **зоны возврата** |
| **Классические EAS / RFID-ворота** | Антикражная метка на выходе | Не учитывают **начальный вес тары** и **накопленные события изменения** в сессии |
| **Касса самообслуживания с весами** | Одно взвешивание на кассе | Нет регистрации тары **на входе**; нет отслеживания **в процессе** сессии в модульной рознице |
| **Системы залоговых тележек/корзин** | Возврат тележки | Нет привязки к **пользовательской сессии** и **ожидаемому весу на выходе** с учётом покупок |
| **Простое «взвешивание на выходе»** | Одно финальное взвешивание | Не различает **подмену тары** (несовпадение ID); не обрабатывает **оставленную** системную тару |

### Ключевые патентуемые акценты

1. **Сквозной контроль:** регистрация на входе → журнал сессии → верификация на выходе (не разовый снимок).  
2. **Предотвращение подмены тары:** непрерывность ID + профиль веса + временная шкала бокового считывателя (пункты 2–3, 7, 10 формулы).  
3. **Несколько тар в сессии:** своя + системная; динамический **активный набор** для выхода.  
4. **Оставление системной тары:** подтверждённый возврат/оставление **не** считается расхождением (пункты 5–6, 16–19).  
5. **Распределение мультисессии** на одном модуле + **событие неоднозначности** (пункты 20–23).  
6. **Двухзонная платформа:** исключение веса пользователя из расчёта (пункты 6–7).  
7. **Режим тары без метки** с пониженной уверенностью (пункт 15).  
8. **Защитная реакция** как структурированный сценарий, а не просто сигнал тревоги (пункты 1(ix), 12).
