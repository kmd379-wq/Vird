THROUGH-TRACKING TARE CONTROL SYSTEM WITH TARE SUBSTITUTION PREVENTION, PROVIDED-TARE LEAVING HANDLING, AND EVENT ALLOCATION ACROSS MULTIPLE SHOPPER SESSIONS  FIELD [0001] The present disclosure relates to autonomous retail systems and, more particularly, to architectures for entry and exit control of a user-carried receptacle, such as a bag, basket, backpack, package, trolley, or other carrier used to transport goods within a retail zone. More specifically, the disclosure relates to solutions in which the initial tare weight of the carrier is registered at entry, changes in the carrier mass are tracked during a user session, and, at exit, the carrier is re-identified and the exit tare weight is compared with an expected weight to detect discrepancies, tare substitution, and other violations. BACKGROUND [0002] Autonomous retail environments may permit users to enter a retail zone, select products without a conventional cashier, and exit through a controlled access point. Users may carry bags, baskets, backpacks, packages, trolleys, or other receptacles whose initial weight can affect the interpretation of weight changes observed during a shopping session. [0003] Where multiple receptacles or multiple shoppers interact with shared retail modules, conventional systems may have difficulty maintaining continuity between a receptacle registered at entry and a receptacle presented at exit, accounting for receptacles provided or collected within the retail zone, and allocating weight-change events to the correct user session. Accordingly, a need exists for improved through-tracking tare control, tare-substitution detection, and event allocation across concurrent user sessions. SUMMARY [0004] In some embodiments, the system includes an entry group configured to require registration of the tare before the start of a user session, one or more retail modules configured to determine tare-change events during the user session, and an exit group configured to perform exit verification of the tare before unlocking an exit barrier. In some embodiments, the system further includes a tare identification module, a tare ID assignment module, a tare profile store, 

[PAGE 2]
and a controller implementing a tare event log, expected exit tare weight calculation, tare continuity verification, and protective-response scenarios. [0005] In some embodiments, the system is configured to account, within a single user session, both for a user-carried receptacle with which the user entered the retail zone and for one or more units of tare provided by the system. A system-provided tare may be issued to the user at entry, in a retail-module area, or in another permitted zone of the complex. If such a system-provided tare is later returned, left in the retail zone in a permitted area, placed in a return area, or otherwise removed from the active tare set of the user session with confirmation by a corresponding sensor event, the controller is configured to modify the active tare set of the user session and exclude the mass of the respective tare from calculation of the expected exit tare weight. [0006] In some embodiments, leaving system-provided tare in the retail zone is not treated as a discrepancy event if the system confirms the permitted nature of the tare being left on the basis of at least one of: reading a tare identifier in a return zone, a weight event in the return zone, visual confirmation of placement of the tare in a permitted zone, a signal from a tare-presence sensor in a storage or return zone, or a combined sensor confirmation. [0007] In some embodiments, the same weight section, shelf, bin, tray, cabinet, or other retail module may simultaneously serve multiple shoppers, while a separate active user session is created and maintained for each shopper. The controller is configured to determine, based on temporal features, camera data, interaction zone, tare identifiers, user trajectory, and a sequence of sensor events, to which particular user session each tare-change event, each item-removal event, each return event, and each placement or permitted-leaving event of system-provided tare belongs. [0008] In some embodiments, during simultaneous interaction of multiple shoppers with the same retail module, the system does not mix withdrawals, returns, weight changes, and other events of different user sessions. If the confidence level for assigning an event to a single user session is insufficient, the controller generates an ambiguity event, associates that event with two or more affected user sessions, and initiates a verification scenario, operation restriction, or protective response. DETAILED DESCRIPTION [0014] The following description provides non-limiting examples of systems, methods, modules, workflows, data structures, and control techniques. The disclosed features may be used individually or in any technically compatible combination. For purposes of this disclosure, a "tare unit" may include a user-carried or system-provided receptacle, carrier, bag, basket, backpack, package, trolley, container, or other article whose weight or identifier is tracked in association with a user session. FIG. 1. Entry and Exit Architecture [0015] With reference to FIG. 1, an example architecture of an autonomous retail system with through-tracking tare control is disclosed. In some embodiments, the system includes an entry group, an exit group, and a retail zone positioned therebetween. The entry group may include an 

[PAGE 4]
entry barrier, an entry monitor, a tare identification interface, and an entry weighing structure. The exit group may include a tare identification interface, an exit weighing structure, a user alert interface, and an exit barrier. [0016] In some embodiments, the entry monitor is configured to display system-use terms including a notice that the user's carried receptacle is subject to mandatory registration, identification, and weighing before the user session begins. In some embodiments, the entry monitor is further configured to display consent terms according to which continuation of the user session and access to the retail zone are permitted only after the user confirms consent to processing of data associated with the carried receptacle, its identifier, and weighing measurements. After receipt of such consent, the system may activate the entry tare-registration procedure. [0017] In some embodiments, the user places the carried receptacle in the entry registration area, where the system either reads a pre-assigned tare identifier or assigns a tare identifier at the beginning of the user session. Simultaneously or sequentially, the initial tare weight is measured and stored in association with the user session. After successful completion of these actions, the controller may allow the user to pass into the interior retail zone. [0018] In some embodiments, the system additionally issues to the user one or more units of tare provided by the system, each such unit being capable of receiving its own tare identifier and its own weight profile. Such system-provided tare may be used by the user within the retail zone and may then either be carried with the user to the exit group, left in a permitted area of the retail zone, or returned to a designated return zone. If leaving or return of such system-provided tare is confirmed by the system, the controller excludes the mass of that tare from calculation of the expected exit tare weight for exit verification. [0019] In some embodiments, upon completion of the user session, the user moves to the exit group and places the active carried receptacle or active carried receptacles in the exit verification area. The exit group reads the tare identifier, measures the exit tare weight, and transmits the corresponding data to the controller. If the tare identifier corresponds to the identifier registered at entry or during the user session, and the exit weight of the active tare corresponds to the expected exit tare weight within an allowable threshold, the exit barrier may be unlocked. Upon detection of a weight discrepancy, a change in tare identifier, absence of a tare identifier, or 

[PAGE 5]
another sign of violation, the system may maintain the exit barrier in a locked state and initiate a protective-response scenario. FIG. 2. Controller and User-Session Architecture [0020] With reference to FIG. 2, an example logical controller architecture for a through-tracking tare control system is disclosed. In some embodiments, the controller is in communication with the entry group, retail modules, exit group, a tare ID assignment module, a tare profile store, and, where applicable, a remote server or cloud platform. [0021] In some embodiments, at the start of a user session, the controller receives from the entry group at least one of: a tare identifier, an indication of issuance of system-provided tare, an initial tare weight, a tare type, and visual features of the tare. Based on such data, the controller may create a user-session record and form a tare profile or retrieve a tare profile from the tare profile store. In some embodiments, the tare profile includes the tare type, a baseline tare weight, an allowable tare-weight deviation range, a tare identifier type, an identification-confidence level, and other parameters used for subsequent tare continuity verification. [0022] In some embodiments, the controller is configured to maintain, within a single user session, multiple units of tare, each associated with its own identifier, weight profile, and status. Such status may indicate, for example, that the tare is active for exit, returned, left in the retail zone, placed in a return zone, temporarily unconfirmed, or excluded from exit-weight calculation. In some embodiments, a system-provided tare, after issuance to the user, is treated as an active tare unit and, after confirmed return or leaving in a permitted zone, is converted into an inactive status for exit reconciliation. [0023] In some embodiments, the same retail module may simultaneously serve multiple shoppers and multiple active user sessions. In that mode, the controller is configured to allocate tare-change events, item-removal events, item-return events, item-placement events into tare, and events involving return or permitted placement of system-provided tare among multiple user sessions on the basis of at least temporal correlation, camera data, interaction zone, user trajectory, tare-identifier data, and sequence of sensor events. [0024] In some embodiments, the retail modules transmit to the controller tare-change events associated with adding items to the carried receptacle, removing items from the carried receptacle, return attempts, partial returns, and other actions affecting the mass of the carried 

[PAGE 6]
receptacle. The controller maintains a tare event log in which events are associated with a particular user session and, where available, with a tare identifier. On the basis of the initial tare weight, the tare event log, and the status of each tare unit, the controller calculates an expected exit tare weight of the active tare. Tare units for which return status or permitted status indicating permitted placement in the retail zone has been confirmed are excluded from calculation of the expected exit tare weight. [0025] In some embodiments, when the confidence level for attributing an event to a single user session is insufficient, the controller generates an ambiguity event and associates that event with two or more potentially affected user sessions. In response to such ambiguity event, the controller may temporarily suspend completion of an operation, request additional sensor confirmation, transfer the corresponding user sessions into a verification mode, temporarily block exit completion of one or more user sessions, initiate inspection, or alert an operator. [0026] In some embodiments, after the user transitions to the exit group, the controller receives an exit tare identifier and an exit tare weight. The controller may perform at least two checks: a tare continuity check by comparing the entry and exit tare identifiers, and a weight-consistency check by comparing the expected exit tare weight of the active tare with the measured exit tare weight of the active tare. Upon detection of a discrepancy, the controller may generate a weight-discrepancy event, a tare-substitution event, an event of ambiguous allocation of events between user sessions, or a combined violation event, and may initiate one or more protective-response scenarios including re-identification, re-weighing, exit locking, routing to an inspection zone, logging the event in an audit log, and alerting an operator. FIG. 3. Dual-Zone Platform [0027] With reference to FIG. 3, an example dual-zone platform suitable for use in the entry group, the exit group, or both groups is disclosed. In some embodiments, the dual-zone platform includes a first zone configured to receive the carried receptacle and a second zone configured to receive the user. The first zone is associated with at least one weighing structure configured to measure the tare weight of the carried receptacle. The second zone may be configured to determine user presence, user position, or load distribution without including such data in the tare-weight calculation. 

[PAGE 7]
[0028] In some embodiments, the controller receives signals from the first and second zones and determines whether the carried receptacle is located in an acceptable position for correct measurement. Upon detecting that the carried receptacle is positioned partially outside the first zone, is being held by the user, is touching the floor, is touching other structures, or has been replaced by another object, the controller may reject the measurement and require repositioning of the carried receptacle. In some embodiments, the dual-zone platform further includes presence sensors, optical sensors, cameras, positioning barriers, or other means for ensuring tare-measurement reliability. [0029] In some embodiments, use of the dual-zone platform allows exclusion of the user's body weight from the calculations and thereby improves the accuracy of registration of the initial tare weight and the exit tare weight. Additionally, the dual-zone platform may be used to detect attempts to circumvent the system by lifting part of the carried receptacle, substituting the tare directly in the weighing area, transferring contents between carriers, or performing other actions capable of distorting the measurement or interrupting tare continuity. FIG. 4. User-Session Workflow [0030] With reference to FIG. 4, an example workflow of a user session in a through-tracking tare control system is disclosed. In some embodiments, the workflow begins with display on the entry monitor of terms of use, a notice regarding the registration and weighing procedure for the carried receptacle, and a user-interface element for obtaining consent. If consent is not received, the entry procedure does not continue and access to the retail zone is not granted. [0031] After consent is confirmed, the system may perform tare identification or tare ID assignment. In various embodiments, the tare identifier may be read from a pre-embedded or attached tag, applied to the carried receptacle during entry registration, assigned by issuance of system-provided tare with an embedded identifier medium, or created as a temporary tare identifier for the duration of the user session. The initial tare weight is then determined, and a tare profile is formed for the current user session. [0032] In some embodiments, during the user session, the retail modules determine tare-change events, which are recorded in the tare event log and used for calculating the expected exit tare weight. In some embodiments, during the user session, system-provided tare is additionally issued to the user, such tare being registered as a separate tare unit within the same user session. 

[PAGE 8]
If such system-provided tare is subsequently returned, left in a permitted area of the retail zone, or placed in a return zone, and this is confirmed by the system, the controller changes the status of the corresponding tare unit and excludes its mass from calculation of the expected exit tare weight. [0033] In some embodiments, the same retail module may simultaneously be used by multiple shoppers. In that case, the system associates each tare-change event, each item-removal event, and each event of return or permitted placement of system-provided tare with a specific user session on the basis of multi-sensor correlation. If unambiguous assignment is impossible, the system generates an ambiguity event and transfers one or more corresponding user sessions into a verification mode until additional confirmation or operator intervention is obtained. [0034] Upon completion of shopping, the user proceeds to the exit group, where re-identification of active tare and re-weighing of active tare are performed. The controller compares the measured exit tare weight of the active tare with the expected exit tare weight of the active tare and additionally verifies tare continuity on the basis of the tare identifier. If verification is successful, the controller permits unlocking of the exit barrier and closes the user session. If a discrepancy is detected or an ambiguity event has not been resolved, the system may initiate a protective response including re-identification, re-weighing, display of a warning to the user, maintenance of the exit barrier in a locked state, transfer of the user into an inspection mode, or alerting an operator.
