## 1. Назначение и область применения

### 1.1. Назначение

Настоящее ТЗ определяет требования к **трём аппаратным модулям** установки Micro Shop MVP:

| ID | Модуль | Роль в шине | Товарный сценарий |
|---|---|---|---|
| **MS-PRODUCE-01** | «Овощ» | Slave | Свежая продукция, выдача из бункера/лотка |
| **MS-CHILL-01** | «Молоко» | **Master** (edge-host) | Охлаждённая молочная категория |
| **MS-MEAL-01** | «Рис с разогревом» | Slave | Готовая еда + индукционный нагрев |

**Master-модуль (MS-CHILL-01)** дополнительно содержит edge-контроллер, сетевой шлюз и точку агрегации шины модулей.

### 1.2. Цель прототипа

Подтвердить на lab-стенде в РФ:

1. Модульную сборку **master + 2 slave** с общей шиной.
2. **Весовую идентификацию SKU** (1 слот = 1 товар) с точностью ≥ 99%.
3. Событие **«товар взят»** → сигнал на backend ≤ 300 мс (local edge).
4. Удержание температуры холодильного модуля **+2…+6 °C**.
5. Безопасный **индукционный нагрев** по команде из app.
6. Непрерывную работу ≥ **7 суток** на lab-площадке.

### 1.3. Что не входит в это ТЗ

- Разработка backend, mobile app, fiscal (отдельные ТЗ).
- Серийный корпус, бренд-дизайн, производство в Китае.
- PPA №10 (контроль тары), биометрия, RFID, vision-AI.
- Полная локация 6–8 шкафов.

### 1.4. Допущения (до подтверждения заказчиком)

| # | Допущение | Альтернатива |
|---|---|---|
| A-01 | Edge-host размещён в MS-CHILL-01 | Отдельный шкаф управления (+4-й модуль — вне scope) |
| A-02 | Lab-площадка: **220 V ±10%, 50 Hz**, 3 фазы или 1 фаза с разведением | Уточняется по адресу |
| A-03 | Идентификация товара — **только вес** | RFID — change request |
| A-04 | Корпус v0 — **металлокаркас + панели** (лабораторный) | ЛДСП/композит допустимы для v0 |
| A-05 | Камера наблюдения — **опционально** на v0 | — |

| Параметр | Значение |
|---|---|

| Влажность | 20–80% без конденсации |
| Пыль | Обычная офисная / складская |
| Установка | В помещении, на ровном основании |
| Освещение | Искусственное, без прямого солнца на холодильный модуль |

### 2.4. Электропитание

| Линия | Потребитель | Номинал (ориентир) |
|---|---|---|
| L1 — «Логика» | Edge, замки, датчики, шина | 220 V, ≤ 300 W на установку |

| L3 — «Индукция» | MS-MEAL-01 | 220 V, ≤ 2 000 W, **отдельный автомат 16 A** |

**Требования:**

- Защитное отключение (УЗО) на группах L2, L3 — рекомендуется.
- ИБП on-line или line-interactive на **L1** (edge + замки): автonomy ≥ 15 мин.
- Заземление обязательно; сопротивление контура ≤ 4 Ω (по нормам lab-помещения).
- Кабельная разводка — в кабель-канале; силовые и сигнальные цепи разделены.

### 2.5. Общая шина модулей (Vertical Bus, упрощённая MVP)

| Параметр | Спецификация |
|---|---|
| Физический интерфейс | **RS-485** (2-wire + GND) или **CAN 2.0** — выбор на этапе v0 |
| Топология | Linear: Master → Produce → Meal (terminators на концах) |
| Скорость | 115 200 baud (RS-485) / 250 kbit/s (CAN) |
| Протокол прикладного уровня | Micro Shop Bus Protocol v0 (MSBP-0) — JSON-over-serial или binary frame *(отдельная спецификация firmware)* |
| Макс. кабель между модулями | ≤ 3 m (lab) |
| Питание 24 V logic на шине | Опционально: общий 24 V DC ≤ 5 A от master PSU |

**Сигналы на каждом slave-модуле (минимум):**

- `DOOR_OPEN`, `DOOR_CLOSED`
- `LOCK_EN`, `LOCK_STATE`
- `WEIGHT_G[n]` — масса по слотам
- `TEMP_C` — температура камеры
- `FAULT_CODE`
- `HEARTBEAT`

### 2.6. Общие требования безопасности

| ID | Требование |
|---|---|
| S-01 | Двери блокируются вне активной сессии покупателя |
| S-02 | При открытии двери > 60 сек — alarm + lock attempt (configurable) |
| S-03 | Аварийная кнопка «STOP» на MS-MEAL-01 — обесточивает индукцию |
| S-04 | При потере связи с edge > 30 сек — slave переводит замки в safe state (locked) |
| S-05 | Корпус модулей: заземление, без острых кромок, finger-trap protection на петлях |
| S-06 | Холодильный агрегат: защита от перегрева компрессора, датчик температуры камеры |
| S-07 | Индукция: датчик присутствия посуды (или контроль тока), auto-shutoff 120 сек |
| S-08 | Материалы, контактирующие с пищей — food-grade там, где применимо (лотки, бункер) |

### 2.7. Общие требования к идентификации товара (вес)

| Параметр | Значение |
|---|---|
| Принцип | 1 SKU ↔ 1 слот с калиброванной tare |
| Тип датчика | Тензорезисторная ячейка, класс не хуже C3 (commercial) |
| Разрешение | ≤ 1 g (produce), ≤ 2 g (chill/meal) |
| Стабильность | Дрейф ≤ ±3 g за 24 ч после калибровки |
| Алгоритм | Stable weight ≥ 200 ms → delta vs baseline → match SKU tolerance |
| Ложное срабатывание | ≤ 1% на 1000 циклов |
| Калибровка | Процедура через admin + этalon груз 100 g / 500 g |

## 3. Модуль MS-PRODUCE-01 «Овощ» (Slave)

### 3.1. Функциональное назначение

Автономная выдача **свежей продукции** (овощи/фрукты в фасовке или насыпью) с фиксацией факта и массы выданного товара.

### 3.2. Товарные слоты MVP

| Слот | Тип | SKU (пример) | Ном. вес, g | Допуск, ±g |
|---|---|---|---|---|
| P-1 | Бункер / лоток | Картофель 1 кг сетка | 1000 | 50 |
| P-2 | Бункер / лоток | Лук 500 г | 500 | 30 |
| P-3 | Лоток | Яблоки 600 г | 600 | 40 |
| P-4 | Лоток | Морковь 500 г | 500 | 30 |
| P-5 | Резерв | — | — | — |

**Итого:** до **5 слотов**, из них минимум **3 активных** для приёмки MVP.

### 3.3. Конструкция

| Узел | Требование |
|---|---|
| Каркас | Сталь 1.5–2 mm или алюминиевый профиль 40×40 |
| Камера | 1 секция, 1 дверь с обзором (опционально — прозрачная вставка) |
| Бункер P-1/P-2 | Угол наклона **~45°** (целевой патентный контур); v0 допускает 40–50° с ручной доработкой |
| Дно бункера | Нержавейка AISI 304 или food-grade пластик |
| Лотки P-3…P-5 | Съёмные, с фиксированным местом на платформе весов |
| Выдача | Гравитационная + направляющие; без мotorized dispenser на v0 |
| Замок | Электромагнитный или моторный latch, holding force ≥ 300 N |
| Петли | С доводчиком, угол открытия 110° |

### 3.4. Весовой контур

| Параметр | Значение |
|---|---|
| Архитектура MVP | **1 тензоячейка на слот** (5 ячеек max) |
| Альтернатива v0 | 1 ячейка на 2 лотка — только если не проходит по точности |
| Платформа | Жёсткая, без прогиба при max load 3 kg |
| Max load на слот | 3 kg |
| Защита от перегруза | Mechanical stop + software limit 120% ном. |

### 3.5. Датчики и исполнительные механизмы

| Компонент | Qty | Назначение |
|---|---|---|
| Load cell + HX711/ADC | 3–5 | Вес по слотам |
| Door reed switch / Hall | 1 | Состояние двери |
| Electromagnetic lock | 1 | Блокировка двери |
| Temp sensor (ambient) | 1 | Температура внутри (контроль, не климат) |
| LED status | 1 strip | Idle / session / fault |
| Slave MCU | 1 | STM32 / ESP32 — опрос датчиков, bus slave |

**Камера:** опционально 1× USB/IP, 720p — для логов, не для SKU ID на v0.

### 3.6. Электрика MS-PRODUCE-01

| Параметр | Значение |
|---|---|
| Питание | 24 V DC от master PSU + local DC-DC |
| Потребление | ≤ 40 W (без нагрузки на замок) |
| Разъёмы | Силовой (к master), bus (IN/OUT), service USB |

### 3.7. Логика работы (hardware level)

1. Получение `SESSION_OPEN` от master → unlock door.
2. Покупатель открывает дверь → `DOOR_OPEN`.
3. Изменение веса слота > порога → `PICK_EVENT(slot_id, delta_g)` → master.
4. Master подтверждает → edge инициирует оплату.
5. `SESSION_CLOSE` или timeout → lock door.

### 3.8. Критерии приёмки MS-PRODUCE-01

| # | Критерий | Метод |
|---|---|---|
| AC-P-01 | 100 циклов open/take/close без заклинивания замка | Автотест |
| AC-P-02 | 99% корректных PICK_EVENT на 3 SKU | 100 попыток |
| AC-P-03 | Время unlock после SESSION_OPEN ≤ 500 ms | Oscilloscope / log |
| AC-P-04 | Бункер 45° обеспечивает выдачу без ручного вмешательства (3 SKU) | Manual test |
| AC-P-05 | FAULT при потере bus связи > 30 сек | Disconnect test |

## 5. Модуль MS-MEAL-01 «Рис с разогревом» (Slave)

### 5.1. Функциональное назначение

1. **Хранение** готовых блюд в контейнерах (охлаждённое +2…+8 °C **или** controlled ambient +15…+22 °C — выбирается один режим для v0).  
2. **Индукционный нагрев** контейнера по команде из app **после** выдачи из слота хранения.

**Решение для v0 (рекомендация):** хранение **охлаждённое +2…+8 °C** (единая холодильная логистика с молоком); нагрев до **+65 °C** min в центре блюда *(lab — с термометром-эталоном)*.

### 5.2. Товарные слоты MVP

| Слот | SKU (пример) | Ном. вес, g | Допуск, ±g |
|---|---|---|---|
| M-1 | Рис с курицей 350 г | 380 | 15 |
| M-2 | Рис с овощами 350 г | 380 | 15 |
| M-3 | Резерв | — | — |

**Итого:** минимум **2 активных SKU**.

### 5.3. Конструкция

| Узел | Требование |
|---|---|
| Секция хранения | 1 дверь, 2–3 слота, охлаждённая камера малого объёма **или** термобокс с Peltier/compressor mini |
| Секция нагрева | Индукционная плита встроенная, зона с маркировкой «нагрев» |
| Разделение | Физическое: нельзя включить индукцию при закрытой/запертой неправильной зоне |
| Контейнер | Стандарт MVP: PP bowl Ø180 mm, совместим с induction (или adapter plate) |
| Аварийная кнопка | Красная mushroom, NC, обесточивает индукцию |
| Вентиляция | Exhaust fan при T_plate > 60 °C |

### 5.4. Индукционный контур

| Параметр | Значение |
|---|---|
| Тип | Built-in induction module, single zone |
| Мощность | 800–1500 W, регулируемая |
| Control | PWM/serial от slave MCU |
| Датчики | Plate temp (IR или NTC), pan detection (current sense) |
| Программа нагрева | Ramp to setpoint + hold; max time **120 sec** |
| Target | Surface/food proxy ≥ 65 °C *(lab validation)* |
| Interlocks | No pan → no start; door open → no start; E-stop → hard off |
| Cooling post-heat | Fan 60 sec after stop |

### 5.5. Весовой контур (хранение)

| Параметр | Значение |
|---|---|
| Load cells | 2–3 (1 на слот) |
| Max load | 1 kg / slot |
| PICK_EVENT | Аналогично produce/chill |

**Нагрев:** оплата за SKU уже списана при PICK; команда `HEAT_START` — отдельное software event без доп. списания на MVP.

### 5.6. Датчики и исполнительные механизмы

| Компонент | Qty | Назначение |
|---|---|---|
| Mini cold unit / Peltier | 1 | Хранение M-1…M-2 |
| Induction module | 1 | Нагрев |
| Load cells | 2–3 | Слоты хранения |
| Plate temp sensor | 1 | Контроль нагрева |
| E-stop | 1 | Безопасность |
| Door sensors | 2 | Хранение + зона нагрева (если раздельные) |
| Locks | 1–2 | По конфигурации |
| Slave MCU | 1 | |
| Exhaust fan | 1 | |

### 5.7. Электрика MS-MEAL-01

| Параметр | Значение |
|---|---|
| L1 Logic | ≤ 60 W |
| L3 Induction | ≤ 2000 W peak — **отдельная линия обязательна** |
| Cold unit | Может питаться от L1 или L2 по схеме lab |
| EMI | Разделение силовых кабелей индукции и сигнальных ≥ 100 mm |

### 5.8. Логика работы (hardware level)

1. Покупатель открывает сессию → unlock door storage.
2. Берёт контейнер M-1 → `PICK_EVENT` → оплата.
3. Кладёт контейнер на зону индукции (или зона уже fixed).
4. App → backend → edge → `HEAT_START(slot, profile_id)`.
5. Slave: verify pan detect → heat profile → `HEAT_DONE` / `HEAT_FAULT`.
6. Покупатель забирает блюдо; timeout очищает зону.

### 5.9. Критерии приёмки MS-MEAL-01

| # | Критерий | Метод |
|---|---|---|
| AC-M-01 | PICK_EVENT 99% на M-1, M-2 | 100 попыток |
| AC-M-02 | Нагрев до ≥ 65 °C (proxy) ≤ 120 сек | 20 циклов с этalon |
| AC-M-03 | E-stop отключает индукцию ≤ 100 ms | Scope test |
| AC-M-04 | No pan → heat blocked | Test |
| AC-M-05 | 100 циклов heat без fault | Endurance |

## 8. Программа испытаний (hardware)

### 8.1. Этапы

| Этап | Объект | Цель |
|---|---|---|
| H0 | Single load cell bench | Калибровка, алгоритм stable weight |
| H1 | MS-PRODUCE-01 standalone | PICK accuracy |
| H2 | MS-CHILL-01 standalone | Temp hold + edge boot |
| H3 | MS-MEAL-01 standalone | PICK + heat safety |
| H4 | Full stack 3 modules | Bus + end-to-end with firmware |
| H5 | 7-day soak test | Reliability |

### 8.2. Протокол H4 (интеграционный)

1. Power on all modules → edge online ≤ 90 sec.  
2. Open session via app/QR → all doors unlock policy check.  
3. Take 1 SKU from each module sequentially → 3 PICK_EVENT → 3 payments.  
4. Heat meal → HEAT_DONE.  
5. Disconnect network 30 sec → events buffered → sync on restore.  
6. Disconnect bus on one slave → safe lock + fault.  
7. Repeat 100 times.

### 8.3. Документы по результатам

- Протокол испытаний H0–H5  
- Журнал температур (CSV)  
- Журнал весовых событий  
- Список отклонений и rework  
- As-built чертежи и фото
