What is claimed is:1. An autonomous retail system with through-tracking tare control, comprising:an entry group and an exit group defining a controlled-passage architecture and configured to control user access to a defined retail zone;a tare identification module associated with the entry group and configured to establish a user session by binding an identifier of at least one carried receptacle to the user session;at least one retail module positioned within the retail zone and including at least one weighing structure configured to determine changes in mass of at least one carried receptacle during the user session and to generate tare-change events corresponding to adding items to the carried receptacle, removing items from the carried receptacle, return of system-provided tare, and leaving of system-provided tare in a permitted area of the retail zone;a tare verification module associated with the exit group and including:(i) a tare identification interface configured to read a tare identifier when an active carried receptacle is positioned in an area of the exit group; and(ii) at least one weighing structure configured to measure an exit weight of active tare; anda controller in communication with the entry group, the retail module, and the exit group, the controller being programmed to:(i) register an initial weight of each tare unit bound to the user session upon establishment of the user session or upon issuance of tare within the retail zone, or determine the weight from stored tare-profile data;(ii) maintain, for the user session, a tare event log reflecting tare-change events determined by the retail module;(iii) maintain, for each tare unit, a status indicating whether the tare unit is to be included in exit verification;(iv) simultaneously maintain multiple active user sessions in relation to the same retail module and allocate tare-change events among the user sessions on the basis of at least temporal correlation, camera data, interaction zone, tare identifier, and sequence of sensor events;(v) calculate an expected exit weight of active tare on the basis of the initial tare weight and tare-change events contained in the tare event log, excluding from such calculation each unit of system-provided tare for which a status of return or permitted placement in the retail zone has been confirmed;(vi) compare the exit weight of active tare measured by the exit group with the expected exit weight of active tare and generate a discrepancy event if a difference exceeds a defined threshold;(vii) ensure continuity of active tare by comparing the tare identifier read at the exit group with the tare identifier bound to the user session and having active status for exit, and generate a tare-substitution event upon mismatch of the identifiers;(viii) generate an ambiguity event if a tare-change event cannot, with a defined confidence level, be attributed to a single user session; and(ix) in response to at least one of the discrepancy event, the tare-substitution event, or the ambiguity event, execute a protective-response scenario that blocks unlocking of the exit barrier and initiates at least one of re-identification of tare, re-weighing, routing to an inspection zone, temporary restriction of completion of the user session, or alerting an operator.Dependent Claims2.
