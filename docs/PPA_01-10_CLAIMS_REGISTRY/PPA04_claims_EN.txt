Claims1. An autonomous retail system comprising: (a) at least one enclosure defining a storage volume for goods; (b) an access barrier configured to selectively permit access to the storage volume; (c) a reconfigurable chassis disposed within the enclosure, the reconfigurable chassis including a vertical backbone configured to provide power and data connectivity at a plurality of vertical positions; (d) a plurality of interchangeable merchandising modules coupled to the reconfigurable chassis, wherein the plurality of interchangeable merchandising modules includes at least two different module types selected from (i) pushers, (ii) hooks, (iii) box-on-scale modules, and (iv) gated gravity feed modules; (e) a sensor suite configured to generate signals indicative of item presence and item movement within the enclosure, the sensor suite including at least two different sensor modalities selected from an RFID antenna array, an imaging sensor, and load cells; and (f) a controller in communication with the access barrier and the sensor suite, the controller programmed to: (i) establish a user session and reserve funds via a pre-authorization; (ii) determine, based on the signals from the sensor suite, an item removal event associated with a given item during the user session; (iii) compute a price for the given item based at least on expiration data associated with the given item; (iv) capture payment for the given item using the reserved funds; and (v) store a transaction record for the item removal event.2. The system of claim 1, wherein the vertical backbone comprises conductive rails or busbars and the plurality of vertical positions correspond to vertically spaced coupling points for shelves and merchandising modules.3. The system of claim 1, further comprising a user-facing smart edge including an LED information strip and an RFID antenna matrix arranged along a front portion of the enclosure, wherein the controller is further programmed to present item-level pricing and availability information via the LED information strip.4. The system of claim 1, wherein the plurality of interchangeable merchandising modules includes a gated gravity feed module comprising an inclined chute, a locking gate, and a weighing structure positioned to receive a dispensed item, and wherein the controller is programmed to lock the locking gate while the weighing structure detects non-zero weight and to unlock the locking gate when the weighing structure returns to zero weight to dispense a subsequent item.5. The system of claim 1, wherein the controller is further programmed to detect a return attempt based on the signals from the sensor suite and, responsive to the return attempt, to apply a penalty only after presenting an affirmative consent control prior to unlocking the access barrier.6. The system of claim 1, wherein establishing the user session comprises receiving a biometric authentication input and/or receiving an optical-code scan of an optical code generated by a mobile application, the optical code encoding or referencing a session token.7. The system of claim 6, wherein reserving funds via the pre-authorization comprises requesting the pre-authorization based on the session token, such that subsequent access for the user session is authorized using the session token without mandatory biometric capture at the enclosure.8. The system of claim 6, wherein the controller is further programmed to verify that an identity associated with a payment instrument selected for the user session matches a registered user profile associated with the session token.9. The system of claim 6, wherein the controller is further programmed to treat the optical-code scan from a know-your-customer (KYC) verified account as sufficient age verification to permit access to restricted goods, without requiring camera-based age verification capture.10. The system of claim 1, wherein the controller is further programmed to generate a fiscal receipt upon capture of payment for the given item and transmit the fiscal receipt to at least one of the mobile application and a registered email address associated with the user session.11. The system of claim 1, wherein the controller is further programmed to split a single user-session transaction into a plurality of settlement legs and to route funds for different items to different payees based on item-level routing rules.12. The system of claim 11, further comprising a multi-tenant inventory architecture in which shelves, slots, or module zones within the enclosure are virtually allocated to different suppliers, and wherein the controller associates each stocked item with a tenant identifier and applies the item-level routing rules based on the tenant identifier.13. The system of claim 12, further comprising a remote supplier interface configured to enable a supplier associated with a given tenant identifier to monitor inventory on allocated shelves and to update prices for items associated with the given tenant identifier in real time independently of other tenant identifiers.14. The system of claim 1, wherein the controller is further programmed to support an induction process in which a tracking tag identifier is associated with product data at a remote location, an inventory manifest comprising the association is uploaded to a remote server, and the controller downloads the inventory manifest to recognize pre-tagged goods upon arrival at the enclosure without local scanning of each good.15. The system of claim 1, wherein the controller maintains a local financial ledger and, during a loss of network connectivity, continues to authorize access based on a locally stored session token or locally stored balance, stores transaction history in the local financial ledger, and reconciles the transaction history asynchronously after network connectivity is restored.16. The system of claim 1, wherein the controller is further programmed to dynamically switch between a standard mode and a restricted mode based on at least one of a type of goods detected within the enclosure, a time-of-day rule, and a remote command, without hardware modification.17. The system of claim 1, wherein the autonomous retail system comprises a clustered installation including a master enclosure and at least one slave enclosure, the master enclosure housing at least one of a payment terminal, a fiscalization module, and a user authentication sensor, the at least one slave enclosure housing at least one lock and at least one sensor that reports to the controller, wherein the controller maintains a single user session and a virtual basket spanning the master enclosure and the at least one slave enclosure such that a user may retrieve goods from multiple enclosures during the user session, and wherein the controller generates a consolidated receipt and performs a single payment capture for the user session.18. A method of operating an autonomous retail cabinet system, the method comprising: (a) associating, at a remote supplier location, tracking tag identifiers with product data including SKU and expiration information; (b) uploading an inventory manifest comprising the associations to a remote server; (c) downloading the inventory manifest to a cabinet controller; (d) initiating a user session at the cabinet controller via biometric input and/or optical-code scanning of an optical code generated by a mobile application; (e) reserving funds via a pre-authorization based on the user session; (f) controlling an access barrier to permit access to a storage volume; (g) determining, using a sensor suite, item removal events during the user session; (h) computing prices for removed items based at least on the expiration information; (i) capturing payment for the removed items; (j) generating a digital receipt and a fiscal receipt associated with the removed items; and (k) transmitting the fiscal receipt to the mobile application and/or a registered email address.19. The method of claim 18, further comprising maintaining a local financial ledger at the cabinet controller and, during loss of network connectivity, continuing to accept the user session, debiting funds against a locally stored balance or pre-authorization token, storing transaction history in the local financial ledger, and reconciling the stored transaction history asynchronously when network connectivity is restored.20. A non-transitory computer-readable medium storing instructions that, when executed by one or more processors of a cabinet controller, cause the cabinet controller to: (a) establish a user session via biometric input and/or optical-code scanning; (b) maintain a multi-tenant inventory mapping between items and tenant identifiers; (c) determine item removal events via sensor fusion; (d) compute dynamic prices using expiration information; (e) split a transaction into settlement legs and route funds to different payees based on item-level routing rules; (f) generate a fiscal receipt upon transaction capture; and (g) store transaction records in a local ledger for asynchronous reconciliation following network recovery.
